# Purpose

Improve repository documentation clarity, structure, and completeness while keeping changes minimal and safe.

# When to Use

Use when the README is missing essential setup, architecture, or usage context.

# Inputs Needed

- The file or section to improve
- The intended audience
- Any scope limits

# Procedure

1. Read the existing README carefully.
2. Identify the smallest useful improvement.
3. Preserve existing intent and system rules.
4. Ask when context is missing.

# Output Format

Return a concise markdown update with clear headings and minimal disruption.

# Safety Rules

- Do not invent project-specific details.
- Do not modify Sentinel core behavior.
- Stay within the requested scope.
